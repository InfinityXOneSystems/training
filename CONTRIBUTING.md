# Contributing to Training Repository

Thank you for your interest in contributing! This document provides guidelines for contributing to the training repository.

## 🤝 How to Contribute

### Reporting Issues

- Use the GitHub issue tracker
- Check if the issue already exists
- Provide a clear description
- Include steps to reproduce (if applicable)

### Submitting Changes

1. **Fork the repository**
   ```bash
   git clone https://github.com/InfinityXOneSystems/training.git
   ```

2. **Create a branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

3. **Make your changes**
   - Follow existing code style
   - Add comments where helpful
   - Test your changes

4. **Commit your changes**
   ```bash
   git commit -m "Add: brief description of your changes"
   ```

5. **Push to your fork**
   ```bash
   git push origin feature/your-feature-name
   ```

6. **Open a Pull Request**
   - Provide a clear description
   - Reference any related issues
   - Wait for review

## 📝 Contribution Types

### Adding Exercises

- Include a clear problem statement
- Provide test cases
- Consider adding hints or starter code
- Include a solution in a separate file

### Adding Examples

- Write clean, well-commented code
- Explain the concept being demonstrated
- Include practical use cases
- Test the code thoroughly

### Adding Resources

- Verify links are working
- Provide context and description
- Categorize appropriately
- Note the target audience level

### Documentation

- Keep language clear and concise
- Use proper formatting
- Check for typos and grammar
- Ensure accuracy

## ✅ Code Style Guidelines

- Use consistent indentation (2 or 4 spaces, depending on language)
- Follow language-specific conventions
- Write meaningful variable and function names
- Add comments for complex logic
- Keep functions focused and small

## 🧪 Testing

- Test your code before submitting
- Include instructions for testing
- Document any dependencies

## 📋 Pull Request Guidelines

- Keep changes focused and atomic
- Write clear commit messages
- Update documentation as needed
- Be responsive to feedback
- Be patient - reviews take time

## 🚫 What Not to Do

- Don't submit solutions to exercises as part of the main codebase
- Don't include large binary files
- Don't copy code without proper attribution
- Don't submit incomplete work

## 💬 Communication

- Be respectful and constructive
- Ask questions if you're unsure
- Provide context in discussions
- Help others when you can
